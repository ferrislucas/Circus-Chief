## Step 1 — New shared utility: `packages/web/src/utils/id.js`

Create the helper (follows existing `utils/` conventions, e.g. `validators.js`):

```js
/**
 * Generate a unique client-side identifier for non-security purposes (UI keys).
 *
 * `crypto.randomUUID()` is only available in secure contexts (HTTPS or
 * localhost/127.0.0.1). Circus Chief is routinely served over plain HTTP on a
 * LAN IP, where the API is `undefined`. Fall back to timestamp + random so UI
 * identity generation never throws on insecure origins.
 */
export function localId(prefix = 'local') {
  if (typeof crypto !== 'undefined' && typeof crypto.randomUUID === 'function') {
    return crypto.randomUUID();
  }
  return `${prefix}-${Date.now()}-${Math.random().toString(36).slice(2)}`;
}
```

Notes:
- Property access on `crypto` (not destructure) so a missing global doesn't throw in odd environments.
- No UUID-format guarantee for the fallback — callers only need uniqueness within a form session.
- **Why not a global polyfill:** narrower blast radius; the helper documents the constraint at the call site. (Rejected in FRD §7.)

## Risks / Rollback

- **Risk:** none functional — the key is a UI-only identifier; persistence keys come from the server (`_serverId`) and are untouched.
- **Fallback collision:** `Math.random` collision odds are negligible for a handful of rows in one form session, and keys only need uniqueness within that session.
- **Rollback:** single-file revert of `useProviderForm.js` restores prior behavior.
